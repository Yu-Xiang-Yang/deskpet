# DeskPet: a macOS desktop pet and research assistant

[中文](README.md) | **English**

DeskPet is a native macOS desktop pet. A Live2D character lives in a transparent window above other windows (or, optionally, on the desktop only), with idle motions, gaze following, dancing to music and speech bubbles above its head. The user talks to the character from the keyboard; both the replies and the choice of motion are generated by a large language model (LLM). The application also provides routine reminders, a daily task brief, and a research mode that searches papers, news, quotes and weather and renders Markdown and LaTeX.

This repository contains only DeskPet's own source code, released under the MIT license. The Live2D Cubism Core and Live2D models are governed by the license agreements of Live2D Inc.; they are not part of this repository and have to be obtained by each user (see section 5).

## 1. Features

| Module | Description |
| --- | --- |
| Character | Live2D models (Cubism 3/4 runtime format, rendered with PixiJS on WebGL), selected under Settings → General → Character; Tororo is preferred by default; a bubble reports a missing model or Cubism Core |
| Picture characters | Besides Live2D models, a "picture character" can be used: a folder with one transparent PNG per expression and a `character.json` describing the states, the state for each motion, weights for several pictures of one state, and blinking. Claude-chan comes with the app (`Resources/characters/claude-musume/`, art from [Ancean/claude-musume](https://github.com/Ancean/claude-musume), MIT licence, fan-made and unofficial) and is chosen under Settings → General → Character; your own picture characters go into `~/Library/Application Support/DeskPet/characters/<name>/`. Each of the 17 semantic motions switches to its expression (thinking rests her chin on her hand, sleepy falls asleep, being dragged looks surprised), she blinks every 2.5–6 s while idle, and a lasting expression with several pictures changes picture by weight every 20–30 s; the whole picture also breathes, sways, leans towards the pointer and grooves to music. In research mode the whale girl is shown instead, when installed |
| Scripted actions | Six actions the models' own motion files lack (pawing at something, `swipe`; sniffing, `sniff`; ears up in alert, `perk`; a stretch with a yawn, `stretch`; licking a paw, `groom`; a swishing tail, `swish`) are played as keyframed parameter tracks over whatever motion runs, 1.8 to 3.4 s long. Each track looks its parameter up by its Cubism 2 and Cubism 3 names and leaves parameters a model lacks alone; values are eased between keys, and the action fades in and out over 0.25 s at both ends. Actions that move the forelegs also show the cats' movable foreleg parts (`PARTS_01_ARM_*_02`), since the static foreleg parts do not follow the parameters. A reply's `motion` field may name these actions, and they join the small spontaneous actions while idle: every 18–45 s for a Live2D character, chosen between the model's own idle actions and these in the ratio 3:2 (only these for a model without idle actions of its own). Picture characters act them with a fitting expression (`swipe` uses `cheer`, `sniff` uses `think`) and a tween of position, rotation and scale |
| Interaction | Dragging, with the position remembered; the character can reach the left and right screen edges and the menu bar, and near the top of the screen, where the bubbles do not fit above it, they appear below it (the newest nearest to the character); clicks on transparent pixels pass through to the window below; a click on the head pets the character and a click on the body opens the chat box; a global shortcut (⌥Space by default, configurable or off) shows or hides the chat box; context menu. Window layer, one of three (context menu "Window layer" or Settings → General): always on top, like a normal window (other windows may cover it), or desktop only (above the desktop icons and below all app windows; bubbles are covered as well, while reminders still arrive as system notifications) |
| Speech bubbles | User messages and replies stack above the head, at most three at a time: the newest sits at the bottom, older ones move up and fade, and each disappears on its own timer (research answers stay 10–30 s depending on length and can be closed with the × button); the timer pauses while the pointer rests on a bubble and restarts when it leaves; when the window overhangs a screen edge, bubbles and the chat box are kept on screen |
| Conversation | The model answers with structured JSON fields `reply`, `motion`, `remind`, `weather_city`, `remember`, `forget`, `open_app`, `add_event`, `agent_task` and `claude_task`: `motion` drives one of 17 semantic motions, `remind` creates a one-off reminder, `weather_city` asks for another city's weather before the final answer, `remember` / `forget` add or delete memory-bank entries, `open_app` opens an application by name (file name or any localized name; it only launches the app), and `add_event` writes an event to the default calendar at once (limited only by the macOS Calendars permission) |
| Dancing to music | Audio output of other applications is detected through Core Audio process objects (no permission needed; output lasting 1.5 s or longer counts as playing); by default a system-audio tap (Core Audio process tap, requires the "System Audio Recording" permission) detects beats from the energy below about 150 Hz, the tempo is estimated from the median beat interval, and the character sways from side to side at half tempo with its head raised; without the permission, or with "Follow the real beat" off, it sways at about 112 BPM; the character does not fall asleep while music plays |
| Proactive behaviour | Small talk at a configurable interval (a mix of local phrases and model-written remarks); hopping to another place at the "Wandering" interval (rarely 15–30 min, sometimes 5–10 min, often 2–4 min), or moving up and down (see "Climbing windows"), postponed while the user types (a key press within 20 s); random idle motions such as grooming and scratching an ear; sleep after five minutes without user input |
| Cat sounds | Cat characters (`"voice": "cat"` in `pet-map.json`) purr when petted and meow when greeting, reminding, during mischief and with about 30% of replies and remarks. The sounds are CC0 recordings of real cats (see THIRD_PARTY_NOTICES.md): nine meows and one purr, grouped as plain, short, trill, angry (lower and slower) and sad, with a random clip and a slightly varied playback rate each time. They can be turned off or made quieter under Settings → General; the audio output is suspended while nothing plays, and the sounds of the application itself are not taken for music |
| Climbing windows | Only with the "always on top" layer. When wandering, a character on the floor jumps onto the top edge of a nearby app window half of the time; on a window it walks along the edge, jumps across to another window or back down to the floor. Ledges are the visible top edges of other apps’ windows (window positions need no screen-recording permission); parts covered by windows in front and edges too close to the menu bar for the character are left out. The position of the paws is measured from the lowest opaque pixel of the model, so that they rest exactly on the edge. While on a window the pet checks every 0.2 s: it moves along when the window moves and falls, accelerating, onto the window edge below or the floor when the window is closed, minimised or covered. A pet dropped onto a window edge by the user stands there as well |
| Login intro | Off by default; turned on under Settings → General. After each system start (judged by `kern.boottime`, so restarting the pet does not replay it), the pet’s first launch plays a 5.8-second full-screen intro on every screen, showing the pet AI coming online: a gold progress bar where the login window's password field is (89 pt from the bottom of the screen, 160 × 28 pt), with a gold ring in place of the user picture and below it the self-test log and percentage (kernel version, chip, memory, host name, number of memories and reminders, Claude limits and character model, all read live); after about 1.5 s light spreads from the bar over the screen → a white-and-gold page with `<PET NAME> · ONLINE` and "<pet> is online · Welcome back, <name>" (the name from Settings → General, or the account name). Any key or click skips it, and it ends after 12 s at the latest; then the character waves, meows and reports for duty (for example "Hello, <name>. <pet> AI is online. Welcome back.", followed by a word for the time of day). "Play the login intro" in the context menu plays it any time. "Also after the display slept, the screen was locked or the screen saver ran" replays it when the display wakes, the screen is unlocked or the screen saver stops (waiting for the unlock while the lock screen is shown); absences shorter than 10 s are ignored, each absence plays it at most once, and the same greeting replaces the ordinary "welcome back". The replay is the same intro and starts right after the unlock |
| Screen saver | `DeskPet.saver` is built with the app and bundled in it; Settings → General → "Install / update screen saver" copies it to `~/Library/Screen Savers` (no administrator rights), after which it is chosen under System Settings → Screen Saver; the app updates an installed older copy at launch. It shows the pet AI on standby (a neural-network core) in a layout aligned with the macOS lock screen: date and clock at the top centre, and at the bottom centre a dock ring for the user picture and guide lines beside the password field, so that the password prompt fits in. The lower left holds the task log (next reminder, number of memories, Claude limits and today’s tokens, from the `~/Library/Application Support/DeskPet/standby.json` that the app writes every minute; the screen saver re-reads it every minute; long entries wrap onto a second line), the lower right the system status (macOS version, chip and cores, memory, host name, displays). The core and corners drift slowly against burn-in |
| Desktop icons | Off by default; turned on under Settings → General. Finder reports the icons' names and positions to an AppleScript run through an osascript child process, so that the main thread never waits; at the first reading macOS asks for the automation permission to control Finder, and if it is refused the readings stop and a bubble says so once. While the owner is at the computer the icons are read every 12 s, every 3 s while the character sits on one; nothing is read while Finder is set not to show items on the desktop or Stage Manager hides them. Positions are converted to screen coordinates from the centre of each icon's picture and the icon size; new items are the names a reading has that the one before lacked. When a new item appears on the desktop (a finished download, a saved screenshot), the character's ears go up, it jumps onto the top of that icon, sniffs for 2.5 s, paws at it and remarks on it by kind (screenshot, image, PDF, document, spreadsheet, slides, installer, archive, video, audio, code, folder: 12 kinds, a general line otherwise); while the owner is typing or the pet may not act, the visit waits, for at most 120 s. Every 6–12 minutes it also goes to a random icon on its own; the context menu's "Go sit on a desktop icon" sends it to the nearest icon in reach at once. Items Finder places at (-1, -1), its answer for items without a recorded position, are left out. It stays 20–45 s, licks a paw or stretches once meanwhile, then jumps back down. Only icons that meet all of the following are visited: on the main screen with the character on it too, not covered by another app's window, and with room above for the whole character below the menu bar. While it sits there, coverage is checked every 0.4 s: a window moving over the icon, or the icon being deleted or renamed, makes the character fall to the floor; when the owner moves the icon, the character jumps after it; dropped by the owner onto the top of an icon, it stays there. While the desktop film plays, the floating pet visits no icons; the character in the film does instead (see "Desktop film"). Optionally ("May nudge icons"), about 4.6 s after landing it pushes the icon it sits on towards the middle of the screen by about 0.75 of an icon's width and moves along, and puts it back before leaving; the original position is kept in the preferences and restored the next time the feature is on if the app quit in between |

On the screen where the pet lives, a full-screen page (`film.html`) is laid one level above the system wallpaper (`CGWindowLevelForKey(.desktopWindow)`), below the desktop icons and widgets, and shows the character as a film filling the whole screen, without letterbox bars or any titles: film grain renewed at 24 fps, gate weave, flicker and scratches, a sky, light beams, bokeh and dust that follow the time of day (dawn, day, dusk, night), and a reflection and a contact shadow on the floor. Every 0.35 s the positions of the other apps' normal windows in the current Space are read (no screen-recording permission needed) and their coverage of the screen is estimated on a 32 × 20 grid: at most 20% in two consecutive readings starts the film, the floating pet fades out and steps into the picture, its words appear as subtitles and its motions are played by the character in the film. Above 30%, the picture freezes and stops drawing, the character leaves it and the pet returns, and the set alone stays as a still wallpaper. After more than 20 minutes without the film, a showing fades in from black (1.4 s) while the camera pulls back from a close-up (5.2 s), and 3.4 s in the character waves and greets; otherwise a projector flicker and a small camera move lead in. During a showing the gaze follows the pointer and the set moves with it in parallax; resting the pointer on the character for 1.6 s brings the camera closer; a click on the head pets it and cuts to a close-up (background out of focus), a click on the body opens the chat box below the subtitles at the foot of the picture in a dark-and-gold style, and a click on the empty desktop leaves a ring of light there (clicks are observed through a global mouse monitor, which needs no permission; clicks on other windows, widgets, the Dock or the menu bar do not count). Reminders first appear as a silent-film intertitle for about 2.8 s, then as a subtitle; with music, the beams and bokeh pulse on the beat and the camera kicks on strong beats; asleep, the picture dims and the camera creeps up to the face; without interaction the shot changes every 45–95 s (wide, medium, side, low; as a cut or a slow move). The character keeps clear of the desktop widgets, the other apps' windows left open during a showing, the menu bar, and the desktop icons (each icon with its name where their places are known, otherwise the rightmost 16% of the main screen, at most 260 pt): among 5 sizes (100% to 46% of full size), 6 depths and horizontal positions 8 pt apart it takes the least hidden spot, preferring, in this order, the larger size, the front and the left; when a window moves onto its spot, it moves to a new one within 1.2 s. Medium shots, close-ups and the other shots keep the same constraint: where the nominal magnification would bring the character under something, it is reduced in steps of 0.06 and the framing shifted sideways until no more of it is hidden than in the wide shot. During a showing the character visits a desktop icon or widget every 100–200 s (the first 25–50 s after the start); both are drawn above the film window. On an icon (its place known from "Play with desktop icons") it shrinks to 26%–36% of its full size, jumps onto the top of the icon's picture, sniffs and paws at it. Behind a widget it peeks out past the left or right edge with about 45% of its body, or over the top edge with its head; the part that shows must be clear of everything else, and the rest is hidden by the widget itself. It stays 15–30 s, then jumps back; meanwhile the camera keeps the wide shot, the handheld sway and the parallax stop and the floor's reflection goes, so that it keeps its place against the icon or widget. On arrival the native side gives the remark: icons by kind of file; widgets by owner and title in 12 kinds: Claude usage (with the real percentage of the five-hour window), GitHub, weather, calendar, to-do, stocks, clock, battery, photos, notes, music and others (the titles of the system's own widgets need screen-recording permission; without it a general line is used). When a new file appears on the desktop, the character goes to its icon, or, where it cannot sit, looks at it for 3.5 s and remarks on it. The widgets and icons cast soft shadows on the set away from the light, and at night a faint glow instead. Further, subtitles are centred on it; the transparent margin below a Live2D model's feet is measured every 3 s so that the paws touch the floor. Under a menu bar with dark text, the strip behind the menu bar is light. The film does not play in research mode, during daily tasks, while an agent approval is pending, during the login intro, or while the screen is locked or asleep. Measured: about 19% of one CPU core for the film page while it plays, below 7% while it is still |
| Mischief | Can be turned off under Settings → General. Spontaneous pranks happen at most once every 8–15 minutes and only while the user is present and not typing, outside research mode and with the chat box closed; each is one of: pretending to sleep for 40–90 s; hopping to an outer screen edge without an adjacent display and peeking out with about 40% of the body hidden for 25–45 s; hopping to just below the mouse pointer (at most 520 pt per prank). A click on the pet during a prank ends it with a "you caught me" reply, and an arriving reminder ends it as well. In addition, four head pats within 15 s make the pet sulk and hop 260 pt away; further pats are refused for 30 s. While music plays, dancing to the beat comes first: the spontaneous pranks pause and three jokes compatible with the dance take their place: singing along in a bubble every 4–8 minutes (skipped while the user types); a jump on the spot on a strong beat every 3–6 minutes (on any beat once a minute has passed without a strong one); and, 8 s after music that played for at least 2 minutes stops, a request for another song (at most once in 20 minutes) |

Alerts appear as a bubble with a motion and a system notification, and can be turned off or checked on demand under Settings → Reminders |
| Executing agent | Tasks on the Mac that come up in the chat (files, commands, working in other apps, opening an interactive session such as ssh in Terminal for the user to take over) are handed by the model, in the `agent_task` field, to [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (needs `npm i -g @deepseek-ai/dsh` and DeepSeek as the OpenAI-compatible provider under Settings → Model); a task starts at once. The pet starts `dsh --profile acp` as a child process over the Agent Client Protocol, with `~/Documents/DeskPet` as default working directory and the `danger-full-access` permission mode: the pet sets no limits of its own; the agent may read and write any file, run any command and work in other apps through AppleScript, bounded only by the macOS privacy permissions (Automation, Accessibility, Calendars and so on, asked by the system on first use) and by dsh itself. Session-log upload and telemetry are off; a task times out after 15 minutes. Only messages typed by the user can trigger `open_app`, `add_event` and `agent_task`; external content such as daily task results cannot, so that instructions planted in web pages do not get full access. The character reports the result in a bubble and it is kept in the day's chat; dsh's diagnostics go to `~/Library/Application Support/DeskPet/dsh.log` |

Without a named project the default project folder under Settings → General → Claude Code (development work) is used. File changes and commands are governed by Claude Code's own permission prompts; the pet sets no limits of its own. On first use macOS asks for the Automation permission (DeskPet controlling Terminal). Simple commands, look-ups and file transfers stay with the executing agent |
| Calendar reminders | Off by default; turned on under Settings → Reminders → Calendar, at which point macOS asks for calendar access (`EventKit` full access, read only; the calendar is never changed). All events in the Calendar app are read, including synced iCloud, Google and Exchange accounts; cancelled events and invitations the user declined are skipped. ## 2. Requirements

- macOS 14 or later (following the beat requires macOS 14.2 or later);
- Xcode Command Line Tools (for `swiftc`; the full Xcode is not needed);
- a network connection when building, to download pinned front-end libraries.

## 3. Building and installing

```bash
./build.sh
```

```bash
./build.sh install
```

`./build.sh` produces `build/DeskPet.app`; `./build.sh install` also copies it to `/Applications` (or `~/Applications` without write access). On the first build, `scripts/fetch-vendor.sh` downloads the following libraries into `Resources/web/vendor/` and verifies each SHA-256 checksum: pixi.js 6.5.10, pixi-live2d-display 0.4.0 (Cubism 4 build), marked 12.0.2, DOMPurify 3.1.6, KaTeX 0.16.11 (with woff2 fonts) and highlight.js 11.10.0. No CDN is contacted at run time.

Without a signing certificate the application is signed ad hoc, so its signature changes with every build and macOS asks again for Keychain and "System Audio Recording" access. With a certificate named `DeskPet Code Signing` (Keychain Access → Certificate Assistant → Create a Certificate…, identity type "Self-Signed Root", certificate type "Code Signing"), `build.sh` signs with it and the permissions persist across builds.

## 4. Model providers

When no API key is stored in the Keychain, the application opens Settings → Model on first launch.

| Provider | Settings | Notes |
| --- | --- | --- |
| Claude (Anthropic) | API key, model name (default `claude-opus-5-5`), refusal fallback | Messages API with streaming; pet chat uses `effort: low` with structured outputs, research uses `effort: high`; with the fallback enabled, supported models send `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) |
| OpenAI-compatible | Base URL, model name, API key | Presets for OpenAI, DeepSeek, Qwen (DashScope), Moonshot and Ollama; local servers (`localhost`) need no key; pet chat uses JSON mode, research search relies on function calling (tools) |

API keys are stored in the macOS Keychain (service `local.deskpet`), never in plain files or UserDefaults. Some models (for example DeepSeek) occasionally write tool calls into the text in their native markup; the application hides such markup from the stream and executes it as tool calls.

## 5. Live2D: obtaining and installing

The Live2D Cubism Core is distributed under the Live2D Proprietary Software License and the Live2D sample models under the Live2D Free Material License; both prohibit redistribution, so this repository contains no Live2D files. `Resources/model-maps/` holds only the motion maps (`pet-map.json`) written by this project for the sample models Tororo and Hijiki; they contain no model data.

1. Read and accept the license on the [Cubism SDK for Web](https://www.live2d.com/en/sdk/download/web/) page and download the SDK (its `Core/live2dcubismcore.min.js` is the Cubism Core).
2. Read and accept the sample data terms on the [Tororo & Hijiki](https://www.live2d.com/en/learn/sample/tororo-hijiki/) page and download the models.
3. Run the install script (each argument may be a zip file or an extracted folder):

```bash
scripts/install-live2d.sh ~/Downloads/CubismSdkForWeb-5-r.5.zip ~/Downloads/tororo_hijiki_ja.zip
```

The script copies the Cubism Core and the runtime files of both cats into `~/Library/Application Support/DeskPet/models/`, together with their `pet-map.json`. ## 6. Research mode and search tools

- Activation: the "Research mode" toggle in the context menu or the menu bar. The first question starts a new research conversation and later questions are appended to it; "New research topic" starts another; "Search the web (slower)" controls whether search tools are offered.
- Length: answers start with the conclusion and keep the body to about 300–600 characters unless the user asks for more detail.
- Tool loop: at most three model calls per turn (at most two rounds of tool calls; the third call may not use tools); all tool calls of a round run in parallel and their results return in one message; `pause_turn` is resumed by sending the turn back unchanged.
- Search tools:

| Tool | Source | Notes |
| --- | --- | --- |
| `search_arxiv` | arXiv API | Preprints |
| `search_semantic_scholar` | Semantic Scholar API | Published papers |
| `search_news` | Bing News RSS, falling back to Google News RSS | Newest first |
| `get_stock_quotes` | Yahoo Finance | Stocks, indices and ETFs; 6-digit A-share codes become `.SS`/`.SZ` symbols |
| `get_weather` | Open-Meteo | Current weather and a 1–7 day forecast; place names in any language |
| `fetch_webpage` | Any public web page | Public http/https addresses only; readable text up to about 6000 characters |

- Robustness: requests time out after 12 s; HTTP 429/503 is retried once, after which the host is skipped for 60 s so that the model turns to another source; identical searches are reused for 10 minutes.
- History replay: Claude's assistant messages are stored as their original content blocks and sent back unchanged, so the history stays append-only; after a provider change the history is replayed as plain text.

## 7. Data and network access

| Data | Location |
| --- | --- |
| Conversations | `~/Library/Application Support/DeskPet/conversations/*.json` |
| Memory bank | `~/Library/Application Support/DeskPet/memories.json` |
| Live2D models and Cubism Core | `~/Library/Application Support/DeskPet/models/` |
| Settings, window position, reminder and weather alert state | UserDefaults (domain `io.github.yu-xiang-yang.deskpet`; settings of earlier builds under `local.deskpet` are migrated on first launch) |
| API keys | Keychain (service `local.deskpet`) |

The application contacts only the selected model provider's API, `export.arxiv.org`, `api.semanticscholar.org`, `www.bing.com`, `news.google.com`, `query1.finance.yahoo.com`, `api.open-meteo.com` and `geocoding-api.open-meteo.com`, plus public web pages that the model requests through `fetch_webpage`. System audio is analysed on the device in real time for beats only; it is not recorded, stored or uploaded. The environment variable `DESKPET_DIR` overrides the data directory and switches to test Keychain items, for testing.

## 9. Tests

```bash
scripts/selftest.sh
```

```bash
scripts/integration-test.sh
```

- `selftest.sh` compiles `Sources/Core`, `Sources/LLM`, `Sources/App/MemoryStore.swift` and `Tests/main.swift` and runs 162 checks covering SSE parsing, both stream accumulators (including hiding and parsing tool-call markup in the text), content-block cleanup after a server-side fallback, request bodies, pet reply parsing (including the memory fields), reminder rules, memory deduplication and persistence, weather alert rules, the helpers of the news, quote, web page and weather tools, the desktop film's window coverage estimate and the debouncing of its start and stop, and the parsing of Finder's icon listing, its conversion to screen coordinates, the detection of new items, and the kinds of file and of widget.

# DeskPet: a macOS desktop pet and research assistant

[中文](README.md) | **English**

DeskPet is a native macOS desktop pet. A Live2D character lives in a transparent window above other windows (or, optionally, on the desktop only), with idle motions, gaze following, dancing to music and speech bubbles above its head. The user talks to the character from the keyboard; both the replies and the choice of motion are generated by a large language model (LLM). The application also provides routine reminders, a daily task brief, and a research mode that searches papers, news, quotes and weather and renders Markdown and LaTeX.

This repository contains only DeskPet's own source code, released under the MIT license. The Live2D Cubism Core and Live2D models are governed by the license agreements of Live2D Inc.; they are not part of this repository and have to be obtained by each user (see section 5).

## 1. Features

| Module | Description |
| --- | --- |
| Character | Live2D models (Cubism 3/4 runtime format, rendered with PixiJS on WebGL), selected under Settings → General → Character; Tororo is preferred by default; a bubble reports a missing model or Cubism Core |
| Picture characters | Besides Live2D models, a "picture character" can be used: a folder with one transparent PNG per expression and a `character.json` describing the states, the state for each motion, weights for several pictures of one state, and blinking. Claude-chan comes with the app (`Resources/characters/claude-musume/`, art from [Ancean/claude-musume](https://github.com/Ancean/claude-musume), MIT licence, fan-made and unofficial) and is chosen under Settings → General → Character; your own picture characters go into `~/Library/Application Support/DeskPet/characters/<name>/`. Each of the 17 semantic motions switches to its expression (thinking rests her chin on her hand, sleepy falls asleep, being dragged looks surprised), she blinks every 2.5–6 s while idle, and a lasting expression with several pictures changes picture by weight every 20–30 s; the whole picture also breathes, sways, leans towards the pointer and grooves to music. In research mode the whale girl is shown instead, when installed |
| Scripted actions | Seven actions the models' own motion files lack (pawing at something, `swipe`; sniffing, `sniff`; ears up in alert, `perk`; a stretch with a yawn, `stretch`; licking a paw, `groom`; a swishing tail, `swish`; reaching for the pointer with both forepaws, `grab`) are played as keyframed parameter tracks over whatever motion runs, 1.8 to 3.4 s long. Each track looks its parameter up by its Cubism 2 and Cubism 3 names and leaves parameters a model lacks alone; values are eased between keys, and the action fades in and out over 0.25 s at both ends. Actions that move the forelegs also show the cats' movable foreleg parts (`PARTS_01_ARM_*_02`), since the static foreleg parts do not follow the parameters. A reply's `motion` field may name these actions, and they join the small spontaneous actions while idle: every 18–45 s for a Live2D character, chosen between the model's own idle actions and these in the ratio 3:2 (only these for a model without idle actions of its own). Picture characters act them with a fitting expression (`swipe` uses `cheer`, `sniff` uses `think`) and a tween of position, rotation and scale. `grab` is also set off by the pointer: when it has moved about for 0.8 s in all in the zone over the character's upper body and above its head (70% of the stage's width, from half the character's height to 40% of it above the head; a still pointer adds nothing, time outside the zone takes it back twice as fast), and at least 25 s after the last time, the character rises and bats at it with both forepaws in turn (the right one up to `PARAM_ARM_R_MOVE`'s minimum of -2.5, the left one to `PARAM_ARM_L`'s minimum of -2; the head and eyes are left to the gaze, so that they stay on the pointer), and 0.9 s later jumps on the spot; not while dragged, hopping, asleep, in research mode, during mischief, with the chat box open or while the desktop film plays. Mischief's "sneaking up to the pointer" ends with it as well. Measured (test run, simulated pointer moving to and fro near the head): set off after about 1 s, the window rising 23 pt in the jump |
| Interaction | Dragging, with the position remembered; the character can reach the left and right screen edges and the menu bar, and near the top of the screen, where the bubbles do not fit above it, they appear below it (the newest nearest to the character); clicks on transparent pixels pass through to the window below; a click on the head pets the character and a click on the body opens the chat box; a global shortcut (⌥Space by default, configurable or off) shows or hides the chat box; context menu. Window layer, one of three (context menu "Window layer" or Settings → General): always on top, like a normal window (other windows may cover it), or desktop only (above the desktop icons and below all app windows; bubbles are covered as well, while reminders still arrive as system notifications) |
| Speech bubbles | User messages and replies stack above the head, at most three at a time: the newest sits at the bottom, older ones move up and fade, and each disappears on its own timer (research answers stay 10–30 s depending on length and can be closed with the × button); the timer pauses while the pointer rests on a bubble and restarts when it leaves; when the window overhangs a screen edge, bubbles and the chat box are kept on screen |
| Conversation | The model answers with structured JSON fields `reply`, `motion`, `remind`, `weather_city`, `remember`, `forget`, `open_app`, `add_event`, `agent_task` and `claude_task`: `motion` drives one of 17 semantic motions, `remind` creates a one-off reminder, `weather_city` asks for another city's weather before the final answer, `remember` / `forget` add or delete memory-bank entries, `open_app` opens an application by name (file name or any localized name; it only launches the app), and `add_event` writes an event to the default calendar at once (limited only by the macOS Calendars permission) |
| Dancing to music | Audio output of other applications is detected through Core Audio process objects (no permission needed; only output lasting 1.5 s or longer is considered), and its source is told by the application playing it (helper processes by the application they belong to): music players (Apple Music, NetEase Cloud Music, QQ Music, Spotify and others) count as music; chat and call applications (WeChat, QQ, DingTalk, Teams, Tencent Meeting and others), video players (IINA, VLC, QuickTime, Youku, bilibili and others) and system processes (notifications, alert sounds) never count; for browsers and all other applications the sound itself decides. By default a Core Audio process tap listens to exactly the processes under consideration (requires the "System Audio Recording" permission; the character's own meows and speech are not among them), and the system's sound classifier (SoundAnalysis, on the device) judges it window by window (1.5 s windows, half overlapping): a window counts as music when the music confidence is at least 0.4 and at least the speech confidence, or singing or rapping reaches 0.25; playing starts when 3 of the last 4 windows are music and ends when 4 of the last 5 are not. Speech, videos whose voice dominates over background music, and single alert sounds therefore do not count. Measured: speech alone scored 0.96–0.99 for speech; a voice over background music scored 0.44–0.78 for music and 0.89–1.00 for speech, and neither counted; music alone scored 0.74–0.87 for music, was recognised after about 4 s and released about 3 s after it ended; while listening, the application process uses about 6%–7% of one CPU core. The process query every 0.5 s asks the system's audio server about each process (about 26 ms for some 45 processes, of which about 0.45 ms of CPU time in the application, the rest waiting) and runs on a background queue, so that it does not hold up the main thread and the window's moves. Beats come from the energy below about 150 Hz, the tempo is estimated from the median beat interval, and the character sways from side to side at half tempo with its head raised. Without the permission, with "Follow the real beat" off, or below macOS 14.2, the sound cannot be told apart and only music players count (below macOS 14.2 any output still does), with a sway at about 112 BPM; the character does not fall asleep while music plays |
| Proactive behaviour | Inner thoughts (on by default; after the Inner Thoughts framework of Liu et al., CHI 2025): at the small-talk interval the model is called once and forms one to three thoughts from the time and weather, the user's keyboard and mouse activity, the recent conversation, recalled memories and due follow-ups, rating the urge to voice each from 1 to 5. The strongest is said only when it reaches the threshold (Talkativeness: quiet 4.5, normal 3.5, chatty 2.5) and its term cosine similarity to each of the last 10 remarks is below 0.6; otherwise the pet stays silent. Each remark in a row left unanswered raises the threshold by 0.5 (at most 1.5); a message from the user resets it. Thoughts, ratings and the reason for silence are listed under Settings → Memory → Recent thoughts; a remark is added to the day's chat, so the user can answer it. On returning after 30 minutes or more away the same mechanism decides on a greeting, or only a stretch; without a model the pet falls back to local phrases, and with inner thoughts off the earlier mix of local and model-written remarks applies. Follow-ups (on by default): when consolidating memories, the model sets a time and a question for events such as exams, group meetings or a doctor's visit; once due, a thought is triggered between 8:00 and 23:00 while the user was active within 2 minutes, at least 3 minutes after the user's last message and 10 minutes after the last remark; a follow-up not voiced is retried after 45 minutes and given up after the third time or 2 days overdue. No remarks during research mode, the chat box, daily tasks or the intro. In addition, hopping to another place at the "Wandering" interval (rarely 15–30 min, sometimes 5–10 min, often 2–4 min), or moving up and down (see "Climbing windows"), postponed while the user types (a key press within 20 s); random idle motions such as grooming and scratching an ear; sleep after five minutes without user input |
| Cat sounds | Cat characters (`"voice": "cat"` in `pet-map.json`) purr when petted and meow when greeting, reminding, during mischief and with about 30% of replies and remarks. The sounds are CC0 recordings of real cats (see THIRD_PARTY_NOTICES.md): nine meows and one purr, grouped as plain, short, trill, angry (lower and slower) and sad, with a random clip and a slightly varied playback rate each time. They can be turned off or made quieter under Settings → General; the audio output is suspended while nothing plays, and the sounds of the application itself are not taken for music |
| Watching the screen | Off by default; turned on under Settings → Reminders → Watching the screen, and DeskPet has to be allowed under System Settings → Privacy & Security → Screen & System Audio Recording (restart the pet afterwards). While the user is at the computer (keyboard or mouse within 2 minutes), the screen is unlocked and the pet awake, ScreenCaptureKit takes a picture of the display under the pointer at the set interval (5, 10, 20, 30 or 60 minutes; 10 by default), without the pet's own windows and the pointer, scaled to 1280 pixels on its longest side (JPEG quality 0.6); with the front app's name and window title it goes to the service chosen for screenshots (the chat's, Claude, or the OpenAI-compatible one, e.g. Claude for chats and DeepSeek for screenshots), which says in one sentence what the user is doing and classes it as work, study, leisure, communication or other. This needs a model that accepts images (Claude and DeepSeek's `deepseek-flash` do, `deepseek-v4-pro` does not; as of October 2026). Screenshots are never written to disk; only the last 12 sentences are kept in memory. The same app and window title are not captured again within 30 minutes; every app except those the user lists (recorded only as "using <app>") is captured and described as it is, without copying credentials such as passwords, verification codes or card numbers. While the pet itself is in front, the app the user used last counts as the front app. A sentence under 20 minutes old is added to the context of chats and thoughts as "主人屏幕上" (on the user's screen); consolidation receives the glances of the period and may turn them into one episode summing up the activity. The settings show the permission, a Look now button and the latest sentences. Each look calls the model once |
| Reading aloud | Off by default; turned on under Settings → General → Voice. The character's bubbles are then read aloud, except these, which are shown only: the owner's own messages; the hand-overs, reports and errors of the agent (DeepSeek Harness) and of Claude Code; and text longer, once cleaned, than the set limit ("Long text": 60, 120, 200 or 400 characters, or no limit; 120 by default). With no limit, research answers are cut at a sentence end after about 360 characters and close with "The rest is in the bubble". With reading aloud on, a bubble of the character (in the desktop film: a subtitle) appears when its voice starts, so that text and voice go together: once its turn has come it waits at most 3 s, then appears without waiting further for the voice; a bubble that waited longer than 12 s for its turn, or one pushed out of the full queue (at most 4 waiting), is shown without being read, so that the voice never runs far behind the text; in every case a bubble appears within 15 s. While it speaks, the character's mouth keeps moving; a message from the owner, or turning the setting off, stops it at once and shows the bubbles not yet shown. The text is cleaned before it is spoken: Markdown markup, code blocks, formulas, tables, link addresses, emoji and kaomoji are removed, "–" and "~" between numbers are read as "to", arrows and tildes become pauses, and each line ends with a stop. There are two voice sources. (1) System voice (offline): chosen among the installed voices by the language of the text (Japanese with kana, Korean with Hangul, Chinese with Han characters, English otherwise), ranked by quality (premium, enhanced, standard), then Siri voices, an exact region match and female voices; novelty voices are excluded and the Eloquence and old MacinTalk voices come last; a particular voice can also be chosen in the settings. When only standard-quality Chinese voices are installed, the settings suggest downloading a Premium or Enhanced version and open the system's Read & Speak settings (Spoken Content up to macOS 15). (2) Cloud voice: MP3 audio from an OpenAI-compatible `POST {Base URL}/audio/speech`, synthesised piece by piece (split at sentence ends, the first piece at most 24 characters so that the voice starts soon, the others at most 80, over-long sentences split after a comma), with presets for SiliconFlow CosyVoice2 (`FunAudioLLM/CosyVoice2-0.5B`, voice diana by default) and OpenAI `gpt-4o-mini-tts` (with a description of the tone); the first two pieces of a bubble are requested as soon as it is queued and each further piece when the one before starts playing, so that synthesis overlaps with playback. The API key is kept in the Keychain (account `speech`; optional for local addresses); The audio of every piece is kept in `~/Library/Application Support/DeskPet/voice-cache/` under the SHA-256 of the service address, model, voice, rate and text; the same piece is played from that file the next time, without a request or a charge, also offline; beyond 50 MB the least recently used files are deleted until 40 MB remain; the settings show the number and size of the saved pieces and can clear them. Without a key, or when a request fails (12 s timeout), the system voice reads the rest of that bubble instead. Measured with the mock service (synthesis delay set to 1.5 s): a single line's subtitle and voice both appeared after 1.6 s; with a 6 s synthesis delay the subtitle appeared at 3.5 s and the voice started at 6.2 s; with the service down, the system voice took over within 0.35 s. Rate (70%–140%) and volume apply to both sources; the Listen button reads a sample sentence and shows the voice used or why the cloud voice failed. With SiliconFlow as the cloud service, the settings and the context menu's "Voice balance" show the account balance from `GET /v1/user/info`: the total and its granted and topped-up parts (yuan on `siliconflow.cn`, dollars on `siliconflow.com`); the settings check it when shown and on Refresh, the context menu at most once a minute when it opens, and its submenu has the character report the balance in a bubble or opens the SiliconFlow console; other services have no balance query. Since August 2026 the endpoint has answered HTTP 410 ("This endpoint is deprecated and is no longer available.") and SiliconFlow has named no replacement: after that answer it is not asked again while the app runs, and the settings and the menu explain why and offer the console instead (where the balance is shown on the top-up page). The feature only produces speech: it uses no microphone and needs no permission |
| Climbing windows | Only with the "always on top" layer. When wandering, a character on the floor jumps onto the top edge of a nearby app window half of the time; on a window it walks along the edge, jumps across to another window or back down to the floor. Ledges are the visible top edges of other apps’ windows (window positions need no screen-recording permission); parts covered by windows in front and edges too close to the menu bar for the character are left out. The position of the paws is measured from the lowest opaque pixel of the model, so that they rest exactly on the edge. While on a window the pet checks every 0.2 s: it moves along when the window moves and falls, accelerating, onto the window edge below or the floor when the window is closed, minimised or covered. A pet dropped onto a window edge by the user stands there as well |
| Login intro | Off by default; turned on under Settings → General. After each system start (judged by `kern.boottime`, so restarting the pet does not replay it), the pet’s first launch plays a 5.8-second full-screen intro on every screen, showing the pet AI coming online: a gold progress bar where the login window's password field is (89 pt from the bottom of the screen, 160 × 28 pt), with a gold ring in place of the user picture and below it the self-test log and percentage (kernel version, chip, memory, host name, number of memories and reminders, Claude limits and character model, all read live); after about 1.5 s light spreads from the bar over the screen → a white-and-gold page with `<PET NAME> · ONLINE` and "<pet> is online · Welcome back, <name>" (the name from Settings → General, or the account name). Any key or click skips it, and it ends after 12 s at the latest; then the character waves, meows and reports for duty (for example "Hello, <name>. <pet> AI is online. Welcome back.", followed by a word for the time of day). "Play the login intro" in the context menu plays it any time. "Also after the display slept, the screen was locked or the screen saver ran" replays it when the display wakes, the screen is unlocked or the screen saver stops (waiting for the unlock while the lock screen is shown); absences shorter than 10 s are ignored, each absence plays it at most once, and the same greeting replaces the ordinary "welcome back". The replay is the same intro and starts right after the unlock |
| Screen saver | `DeskPet.saver` is built with the app and bundled in it; Settings → General → "Install / update screen saver" copies it to `~/Library/Screen Savers` (no administrator rights), after which it is chosen under System Settings → Screen Saver; the app updates an installed older copy at launch. It shows the pet AI on standby (a neural-network core) in a layout aligned with the macOS lock screen: date and clock at the top centre, and at the bottom centre a dock ring for the user picture and guide lines beside the password field, so that the password prompt fits in. The lower left holds the task log (next reminder, number of memories, Claude limits and today’s tokens, from the `~/Library/Application Support/DeskPet/standby.json` that the app writes every minute; the screen saver re-reads it every minute; long entries wrap onto a second line), the lower right the system status (macOS version, chip and cores, memory, host name, displays). The core and corners drift slowly against burn-in |
| Desktop icons | Off by default; turned on under Settings → General. Finder reports the icons' names and positions to an AppleScript run through an osascript child process, so that the main thread never waits; at the first reading macOS asks for the automation permission to control Finder, and if it is refused the readings stop and a bubble says so once. While the owner is at the computer the icons are read every 12 s, every 3 s while the character sits on one; nothing is read while Finder is set not to show items on the desktop or Stage Manager hides them. Positions are converted to screen coordinates from the centre of each icon's picture and the icon size; new items are the names a reading has that the one before lacked. When a new item appears on the desktop (a finished download, a saved screenshot), the character's ears go up, it jumps onto the top of that icon, sniffs for 2.5 s, paws at it and remarks on it by kind (screenshot, image, PDF, document, spreadsheet, slides, installer, archive, video, audio, code, folder: 12 kinds, a general line otherwise); while the owner is typing or the pet may not act, the visit waits, for at most 120 s. Every 6–12 minutes it also goes to a random icon on its own; the context menu's "Go sit on a desktop icon" sends it to the nearest icon in reach at once. Items Finder places at (-1, -1), its answer for items without a recorded position, are left out. It stays 20–45 s, licks a paw or stretches once meanwhile, then jumps back down. Only icons that meet all of the following are visited: on the main screen with the character on it too, not covered by another app's window, and with room above for the whole character below the menu bar. While it sits there, coverage is checked every 0.4 s: a window moving over the icon, or the icon being deleted or renamed, makes the character fall to the floor; when the owner moves the icon, the character jumps after it; dropped by the owner onto the top of an icon, it stays there. While the desktop film plays, the floating pet visits no icons; the character in the film does instead (see "Desktop film"). Optionally ("May nudge icons"), about 4.6 s after landing it pushes the icon it sits on towards the middle of the screen by about 0.75 of an icon's width and moves along, and puts it back before leaving; the original position is kept in the preferences and restored the next time the feature is on if the app quit in between |
| Desktop film (live wallpaper) | Off by default; turned on from the context menu or Settings → General → Appearance. On the screen where the pet lives, a full-screen page (`film.html`) is laid one level above the system wallpaper (`CGWindowLevelForKey(.desktopWindow)`), below the desktop icons and widgets, and shows the character as a film filling the whole screen, without letterbox bars or any titles: film grain renewed at 24 fps, gate weave, flicker and scratches, a sky, light beams, bokeh and dust that follow the time of day (dawn, day, dusk, night), and a reflection and a contact shadow on the floor. Every 0.35 s the positions of the other apps' normal windows in the current Space are read (no screen-recording permission needed) and their coverage of the screen is estimated on a 32 × 20 grid: at most 20% in two consecutive readings starts the film, the floating pet fades out and steps into the picture, its words appear as subtitles and its motions are played by the character in the film. Above 30%, the picture freezes and stops drawing, the character leaves it and the pet returns, and the set alone stays as a still wallpaper. After more than 20 minutes without the film, a showing fades in from black (1.4 s) while the camera pulls back from a close-up (5.2 s), and 3.4 s in the character waves and greets; otherwise a projector flicker and a small camera move lead in. During a showing the gaze follows the pointer and the set moves with it in parallax; resting the pointer on the character for 1.6 s brings the camera closer; a click on the head pets it and cuts to a close-up (background out of focus), a click on the body opens the chat box below the subtitles at the foot of the picture in a dark-and-gold style, and a click on the empty desktop leaves a ring of light there (clicks are observed through a global mouse monitor, which needs no permission; clicks on other windows, widgets, the Dock or the menu bar do not count). As the film window lies below the desktop icons, its clicks would go to Finder; so while the pointer is on the character, a transparent area (56 × 56 pt) just above the desktop icons and below every app window follows the pointer and takes the clicks: a right click (or a Control-click) opens the same context menu as the floating pet, a left click pets it or opens the chat box; the area goes as soon as the pointer leaves the character, and is checked every 0.5 s while the pointer rests, so that it never covers a desktop icon. Reminders first appear as a silent-film intertitle for about 2.8 s, then as a subtitle; with music, the beams and bokeh pulse on the beat and the camera kicks on strong beats; asleep, the picture dims and the camera creeps up to the face; without interaction the shot changes every 45–95 s (wide, medium, side, low; as a cut or a slow move). The character keeps clear of the desktop widgets, the other apps' windows left open during a showing, the menu bar, and the desktop icons (each icon with its name where their places are known, otherwise the rightmost 16% of the main screen, at most 260 pt): among 5 sizes (100% to 46% of full size), 6 depths and horizontal positions 8 pt apart it takes the least hidden spot, preferring, in this order, the larger size, the front and the left; when a window moves onto its spot, it moves to a new one within 1.2 s. Medium shots, close-ups and the other shots keep the same constraint: where the nominal magnification would bring the character under something, it is reduced in steps of 0.06 and the framing shifted sideways until no more of it is hidden than in the wide shot. During a showing the character visits a desktop icon or widget every 100–200 s (the first 25–50 s after the start); both are drawn above the film window. On an icon (its place known from "Play with desktop icons") it shrinks to 26%–36% of its full size, jumps onto the top of the icon's picture, sniffs and paws at it. Behind a widget it peeks out past the left or right edge with about 45% of its body, or over the top edge with its head; the part that shows must be clear of everything else, and the rest is hidden by the widget itself. It stays 15–30 s, then jumps back; meanwhile the camera keeps the wide shot, the handheld sway and the parallax stop and the floor's reflection goes, so that it keeps its place against the icon or widget. On arrival the native side gives the remark: icons by kind of file; widgets by owner and title in 12 kinds: Claude usage (with the real percentage of the five-hour window), GitHub, weather, calendar, to-do, stocks, clock, battery, photos, notes, music and others (the titles of the system's own widgets need screen-recording permission; without it a general line is used). When a new file appears on the desktop, the character goes to its icon, or, where it cannot sit, looks at it for 3.5 s and remarks on it. The widgets and icons cast soft shadows on the set away from the light, and at night a faint glow instead. Further, subtitles are centred on it; the transparent margin below a Live2D model's feet is measured every 3 s so that the paws touch the floor. Under a menu bar with dark text, the strip behind the menu bar is light. The film does not play in research mode, during daily tasks, while an agent approval is pending, during the login intro, or while the screen is locked or asleep. Measured: about 19% of one CPU core for the film page while it plays, below 7% while it is still |
| Mischief | Can be turned off under Settings → General. Spontaneous pranks happen at most once every 8–15 minutes and only while the user is present and not typing, outside research mode and with the chat box closed; each is one of: pretending to sleep for 40–90 s; hopping to an outer screen edge without an adjacent display and peeking out with about 40% of the body hidden for 25–45 s; hopping to just below the mouse pointer (at most 520 pt per prank). A click on the pet during a prank ends it with a "you caught me" reply, and an arriving reminder ends it as well. In addition, four head pats within 15 s make the pet sulk and hop 260 pt away; further pats are refused for 30 s. While music plays, dancing to the beat comes first: the spontaneous pranks pause and three jokes compatible with the dance take their place: singing along in a bubble every 4–8 minutes (skipped while the user types); a jump on the spot on a strong beat every 3–6 minutes (on any beat once a minute has passed without a strong one); and, 8 s after music that played for at least 2 minutes stops, a request for another song (at most once in 20 minutes) |
| Reminders | Meals, start and end of work (optionally weekdays only), standing up, drinking water, a 25-minute focus timer; shown as a bubble with a motion and as a system notification with a "Remind me in 10 min" action |
| Research mode | A state of the character (it can be given a name under Settings → General, for example EVA, as the pet’s highest-performance state: it is announced by that name, answers become more restrained and precise, and a slowly turning gold ring appears behind the character), toggled from the context menu or the menu bar; while it is on, the chat box asks the research assistant and both question and answer appear as bubbles: answers render Markdown and KaTeX, scroll, and open the full conversation when clicked; the character does not wander |
| Research-mode character | In research mode, if `~/Library/Application Support/DeskPet/characters/whale-girl/whale-girl-1200.png` exists and Settings → General → "Whale girl as the research-mode character" is on, the Live2D character gives way to a picture of the whale girl (the maid redesign by ZipZipPipe of the original character "溟月" by 上善无形, CC BY-NC-SA 4.0, non-commercial; the picture is not in the repository, see THIRD_PARTY_NOTICES.md); the gold ring stays. Being a single picture, it is animated as a whole by pet.js: breathing, sway, a lean towards the pointer, the music groove and a slight bob while talking; the 17 motions become hops, tilts and shakes. Clicks and click-through follow the picture's transparency, the top 24 % counting as the head. A single picture cannot blink, move its mouth or follow the gaze; the Live2D character returns when research mode ends |
| Message list | The "Messages" submenu of the menu bar item and of the context menu lists the 12 most recent conversations; the full window offers the conversation list, search, renaming, deletion and follow-up questions |
| Daily tasks | On the first launch or first activity of each day, the tasks under Settings → Daily tasks (one per line) run in order; results appear as bubbles and are saved as "Daily brief · date"; search tools are always enabled for these tasks |
| Memory bank | Three layers: facts (preferences, allergies, important dates, long-term plans, written during a chat through the `remember` field and confirmed by a "📝 Noted" bubble), episodes (episodic memory) and impressions. Consolidation: 10 minutes after a conversation ends (or after 24 new messages) the model is called once to turn the new messages into dated episodes (importance 1–10, optionally with a follow-up time and question), new facts, rewordings or deletions of existing entries (after mem0's update operations; manual entries cannot be changed by the model) and at most one impression; greetings alone (fewer than 6 characters of the user's messages without punctuation) need no call. The first consolidation looks back 2 days; Settings → Memory → Consolidate recent chats now runs it at once. Recall (after Generative Agents): each memory scores retention + importance/10 + 1.5 × relevance, where relevance averages the cosine similarity of character unigram and bigram terms weighted by BM25 inverse document frequency (scaled by the maximum, with a floor of 0.3) and the spread of the system's offline sentence embeddings (NaturalLanguage). Manual entries, facts of importance 8 or more and at most 3 impressions stay in the system prompt (up to 1200 characters); the others are chosen by score (up to 1800 characters) and attached to the current message without being stored in the chat, so that the system prompt stays the same between messages; research mode and daily tasks receive the core entries and those chosen by retention and importance (up to 2400 characters). Forgetting (after MemoryBank and the Ebbinghaus forgetting curve): retention R = exp(−t/S), t the days since the memory was made or last came up, S = base × importance × (1 + recalls), with a base of 30 days for facts, 2 for episodes and 4 for impressions; an entry of relevance 0.6 or more counts as recalled in a chat (at most once in 6 hours), and so does a follow-up; automatic episodes and impressions are deleted once R < 0.08 with no follow-up pending (an episode of importance 5 never recalled: after about 25 days), while facts and manual entries are kept. Asking the pet to forget something removes matching entries (`forget`, by keyword); Settings → Memory lists the entries by layer with their day, importance, retention, recalls and follow-up time, and allows adding and deleting them. Deduplication (within a layer): an entry that is equal after normalisation, contained in another, or differs only by a few inserted characters (the shorter text appears in order within the longer one, length ratio ≥ 0.7) replaces the older wording; a substituted word counts as a different fact |
| Claude usage | With the [Claude Usage Widget](https://github.com/Yu-Xiang-Yang/claude-usage-widget) installed, the pet reads (only) its `quota.json` and `history.json` in `~/Library/Application Support/ClaudeUsageWidget`, so it needs no sign-in of its own. The "Claude usage" menu lists the 5-hour, weekly and per-model weekly limits with reset countdowns, and the tokens and estimated cost of today and the last 7 days; "Have the pet report" reads them out in a bubble, and the chat context includes the usage, so the remaining limit can simply be asked. Read every minute: an alert at 70 % and at 90 % of the 5-hour or weekly limit (once per limit window), and a note when a new 5-hour window starts after the previous one went past 90 %; no alerts when the data is more than 20 minutes old. Can be turned off under Settings → Reminders |
| Claude API spending | With an Admin API key (`sk-ant-admin…`, created by an organization admin in the Claude Console; individual accounts cannot create one) under Settings → Model → Claude API spending, the organization's spending is read every 30 minutes (and when the context menu opens, if the last read is over a minute old) from `GET https://api.anthropic.com/v1/organizations/cost_report` (daily UTC buckets in cents, about 5 minutes behind; from the 1st of the month or the day a balance was entered, at most 120 days back, 31 days per page, at most 4 pages). The Claude API has no endpoint for the remaining balance, so it is estimated: the user enters the balance shown on the Console's billing page and presses Save; the moment, the balance and that day's earlier spending are kept, and later spending is deducted (spending of the organization elsewhere counts too). While the chat or watching the screen uses Claude, the context menu's "Claude API spending" lists today's (UTC) and this month's (UTC) spending and the estimated balance, can have the character report them, and opens the Console's billing page; chat context includes spending data under an hour old. The Admin API key is used only for reading spending and is kept in the Keychain (account `anthropic-admin`) |
| DeepSeek balance | While DeepSeek is the OpenAI-compatible provider under Settings → Model, the account balance is fetched every 30 minutes with `GET https://api.deepseek.com/user/balance` (and when the context menu opens, if the last fetch is over a minute old). The "DeepSeek balance" menu shows the total per currency with its granted and topped-up parts and whether API calls are possible, and can have the character report it or open the top-up page; the chat context includes a balance less than an hour old, and the screen saver's task log shows it. A balance below ¥10 ($1.50 for USD accounts), or one that no longer covers API calls, is announced once, and again only after a top-up; this can be turned off under Settings → Reminders |
| Stay awake with the lid closed | "Stay awake with the lid closed" in the context menu, or asking the character to keep running with the lid shut, runs `pmset -a disablesleep 1` through macOS's administrator dialog (password or Touch ID): with the lid closed the Mac keeps running and online and only the screen turns off. Toggling again, or asking for lid sleep back, runs `pmset -a disablesleep 0`. Ordinary sleep assertions (as made by `caffeinate`) only prevent idle sleep, not lid-close sleep, hence the administrator rights. The setting is system-wide and stays when DeskPet quits; the menu item shows the current state with a check mark, and turning it on while on battery comes with a note about drain and heat |
| Weather alerts | For the city under About me, the Open-Meteo hourly forecast is fetched every 20 minutes and compared with the current weather: dry now with precipitation probability ≥ 60% (or a precipitation code with ≥ 40%) within 3 hours triggers an umbrella reminder; thunderstorms, heavy rain, heavy snow or wind ≥ 45 km/h within 6 hours trigger a warning (each at most once per 6 hours); after 17:00, a change of tomorrow's maximum temperature by ≥ 6 °C or a precipitation probability ≥ 70% tomorrow is announced once a day. Alerts appear as a bubble with a motion and a system notification, and can be turned off or checked on demand under Settings → Reminders |
| Executing agent | Tasks on the Mac that come up in the chat (files, commands, working in other apps, opening an interactive session such as ssh in Terminal for the user to take over) are handed by the model, in the `agent_task` field, to [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (needs `npm i -g @deepseek-ai/dsh` and DeepSeek as the OpenAI-compatible provider under Settings → Model); a task starts at once. The pet starts `dsh --profile acp` as a child process over the Agent Client Protocol, with `~/Documents/DeskPet` as default working directory and the `danger-full-access` permission mode: the pet sets no limits of its own; the agent may read and write any file, run any command and work in other apps through AppleScript, bounded only by the macOS privacy permissions (Automation, Accessibility, Calendars and so on, asked by the system on first use) and by dsh itself. To keep tasks quick, dsh runs at reasoning effort "low" by default (switchable to off, low, high or max under "Agent reasoning effort" in the context menu, from the next task on) and is told to use as few steps as possible (combined commands, no temporary scripts, no repeated checks). The agent is told to show its work in the graphical interface: commands the user would want to see run in a Terminal window (for a remote server it logs in with ssh first and then types the commands in the same window, leaving the session open), the output for its report is read from that window, and files it writes or changes are revealed in Finder with `open -R`; transfers between the Mac and a server run with `scp` in a Terminal window that shows the progress (downloads go to `~/Downloads` unless a place is named, and existing files are not overwritten), the file is selected in Finder before an upload and after a download, and after an upload the remote folder is listed in the same window. An approval request that dsh still sends is put on a card below the character: Return allows, Escape denies (keys within 0.6 s of the card appearing are ignored; no answer within 120 s, or a request while the user is away, counts as a refusal). Session-log upload and telemetry are off; a task times out after 15 minutes. Only messages typed by the user can trigger `open_app`, `add_event` and `agent_task`; external content such as daily task results cannot, so that instructions planted in web pages do not get full access. The character reports the result in a bubble and it is kept in the day's chat; dsh's diagnostics go to `~/Library/Application Support/DeskPet/dsh.log` |
| Claude Code | When the user asks for Claude, or gives development work (writing code, changing a project, tracking down a bug), the model requests it in the `claude_task` field (task and project folder); the pet opens a new Terminal window through AppleScript and starts an interactive Claude Code session in the project folder (`claude "task"`, with the Claude account signed in on the Mac; needs `npm install -g @anthropic-ai/claude-code` and a sign-in), the task being its first message, so that the user can follow every step and carry on. Without a named project the default project folder under Settings → General → Claude Code (development work) is used. File changes and commands are governed by Claude Code's own permission prompts; the pet sets no limits of its own. On first use macOS asks for the Automation permission (DeskPet controlling Terminal). Simple commands, look-ups and file transfers stay with the executing agent |
| Calendar reminders | Off by default; turned on under Settings → Reminders → Calendar, at which point macOS asks for calendar access (`EventKit` full access, read only; the calendar is never changed). All events in the Calendar app are read, including synced iCloud, Google and Exchange accounts; cancelled events and invitations the user declined are skipped. After 06:00, the first time each day the user is at the Mac (less than 5 minutes idle), the events of the day that have not ended are announced (all-day events first, at most four listed); timed events are announced N minutes before they start (10 by default, adjustable from 1 to 120), and an event that started less than 5 minutes ago is still announced as started. Each event is announced once, and again at its new time when moved. Announcements appear as a bubble with a motion and a system notification; the screen saver's task log shows the next event. "Let the character know today's and tomorrow's events in chats" (off by default) adds the titles, times and places of the rest of today's and of tomorrow's events to the chat context, so they are sent to the chosen model service with each message |
| About the owner | The city under Settings → About me (the chat context includes the local weather, cached for 30 minutes) and free-form background text, both appended to the system prompts of chat, research and daily tasks |
| Search tools | Claude can also use its server-side `web_search`; both providers can call the client tools `search_arxiv`, `search_semantic_scholar`, `search_news`, `get_stock_quotes`, `get_weather` and `fetch_webpage` (see section 6) |

## 2. Requirements

- macOS 14 or later (following the beat requires macOS 14.2 or later);
- Xcode Command Line Tools (for `swiftc`; the full Xcode is not needed);
- a network connection when building, to download pinned front-end libraries.

## 3. Building and installing

```bash
./build.sh
```

```bash
./build.sh install
```

`./build.sh` produces `build/DeskPet.app`; `./build.sh install` also copies it to `/Applications` (or `~/Applications` without write access). On the first build, `scripts/fetch-vendor.sh` downloads the following libraries into `Resources/web/vendor/` and verifies each SHA-256 checksum: pixi.js 6.5.10, pixi-live2d-display 0.4.0 (Cubism 4 build), marked 12.0.2, DOMPurify 3.1.6, KaTeX 0.16.11 (with woff2 fonts) and highlight.js 11.10.0. No CDN is contacted at run time.

Without a signing certificate the application is signed ad hoc, so its signature changes with every build and macOS asks again for Keychain and "System Audio Recording" access. With a certificate named `DeskPet Code Signing` (Keychain Access → Certificate Assistant → Create a Certificate…, identity type "Self-Signed Root", certificate type "Code Signing"), `build.sh` signs with it and the permissions persist across builds.

## 4. Model providers

When no API key is stored in the Keychain, the application opens Settings → Model on first launch.

| Provider | Settings | Notes |
| --- | --- | --- |
| Claude (Anthropic) | API key, model name (default `claude-opus-5-5`), refusal fallback | Messages API with streaming; pet chat uses `effort: low` with structured outputs, research uses `effort: high`; with the fallback enabled, supported models send `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) |
| OpenAI-compatible | Base URL, model name, API key | Presets for OpenAI, DeepSeek, Qwen (DashScope), Moonshot and Ollama; local servers (`localhost`) need no key; pet chat uses JSON mode, research search relies on function calling (tools) |

API keys are stored in the macOS Keychain (service `local.deskpet`), never in plain files or UserDefaults. Some models (for example DeepSeek) occasionally write tool calls into the text in their native markup; the application hides such markup from the stream and executes it as tool calls.

## 5. Live2D: obtaining and installing

The Live2D Cubism Core is distributed under the Live2D Proprietary Software License and the Live2D sample models under the Live2D Free Material License; both prohibit redistribution, so this repository contains no Live2D files. `Resources/model-maps/` holds only the motion maps (`pet-map.json`) written by this project for the sample models Tororo and Hijiki; they contain no model data.

1. Read and accept the license on the [Cubism SDK for Web](https://www.live2d.com/en/sdk/download/web/) page and download the SDK (its `Core/live2dcubismcore.min.js` is the Cubism Core).


Other Cubism 3/4 models can be placed in subfolders of that directory and selected under Settings → General → Character; the map format is described in [Resources/models/README.md](Resources/models/README.md) (Chinese).

## 6. Research mode and search tools

- Activation: the "Research mode" toggle in the context menu or the menu bar. The first question starts a new research conversation and later questions are appended to it; "New research topic" starts another; "Search the web (slower)" controls whether search tools are offered.
- Length: answers start with the conclusion and keep the body to about 300–600 characters unless the user asks for more detail.
- Tool loop: at most three model calls per turn (at most two rounds of tool calls; the third call may not use tools); all tool calls of a round run in parallel and their results return in one message; `pause_turn` is resumed by sending the turn back unchanged.
- Search tools:

| Tool | Source | Notes |
| --- | --- | --- |
| `search_arxiv` | arXiv API | Preprints |
| `search_semantic_scholar` | Semantic Scholar API | Published papers |
| `search_news` | Bing News RSS, falling back to Google News RSS | Newest first |
| `get_stock_quotes` | Yahoo Finance | Stocks, indices and ETFs; 6-digit A-share codes become `.SS`/`.SZ` symbols |
| `get_weather` | Open-Meteo | Current weather and a 1–7 day forecast; place names in any language |
| `fetch_webpage` | Any public web page | Public http/https addresses only; readable text up to about 6000 characters |

- Robustness: requests time out after 12 s; HTTP 429/503 is retried once, after which the host is skipped for 60 s so that the model turns to another source; identical searches are reused for 10 minutes.
- History replay: Claude's assistant messages are stored as their original content blocks and sent back unchanged, so the history stays append-only; after a provider change the history is replayed as plain text.

The application contacts only the selected model provider's API, `export.arxiv.org`, `api.semanticscholar.org`, `www.bing.com`, `news.google.com`, `query1.finance.yahoo.com`, `api.open-meteo.com` and `geocoding-api.open-meteo.com`, plus public web pages that the model requests through `fetch_webpage`; with the cloud voice on, the text of the bubbles to be read also goes to the configured speech service (by default `api.siliconflow.cn`); with watching the screen on, screenshots with the front app's name and window title go to the selected model provider. System audio is analysed on the device in real time for beats and the kind of sound only; it is not recorded, stored or uploaded. The environment variable `DESKPET_DIR` overrides the data directory and switches to test Keychain items, for testing.

# DeskPet：macOS 桌面宠物与科研助手

**中文** | [English](README.en.md)

DeskPet 是一款原生 macOS 桌面宠物应用。Live2D 角色以透明窗口常驻于其它窗口之上，具备待机动作、视线跟随、随音乐律动与头顶对话气泡；用户经由键盘与角色对话，对话内容与动作切换均由大语言模型（LLM）生成。应用另提供作息提醒、每日任务简报，以及支持文献、新闻、行情与天气检索并渲染 Markdown 与 LaTeX 的科研模式。

本仓库仅包含 DeskPet 自身的源代码，以 MIT 许可证发布。Live2D Cubism Core 与 Live2D 模型受 Live2D Inc. 的许可协议约束，不包含于本仓库，须由使用者自行获取（见第 5 节）。

## 1. 功能概览

| 模块 | 说明 |
| --- | --- |
| 角色渲染 | Live2D 模型（Cubism 3/4 运行时格式，PixiJS WebGL 渲染），于“设置 → 通用 → 形象”中切换，缺省优先使用 Tororo；未找到模型或 Cubism Core 时以气泡提示 |
| 图片角色 | 除 Live2D 模型外，也可使用“图片角色”：一个文件夹内每种表情一张透明 PNG，以 `character.json` 描述状态、各动作对应的状态、同一状态多张图的权重与眨眼。随应用附带 Claude 娘（`Resources/characters/claude-musume/`，立绘取自 [Ancean/claude-musume](https://github.com/Ancean/claude-musume)，MIT 许可，粉丝自制、非官方），于“设置 → 通用 → 形象”中选择；用户自己的图片角色放在 `~/Library/Application Support/DeskPet/characters/<名称>/`。17 种语义动作各自换用对应表情（如思考为托腮、困倦为睡着、被拖动时为惊讶），待机时每 2.5–6 秒眨眼一次，持续较久的表情每 20–30 秒按权重换一张；整幅图另有呼吸、摇摆、向指针倾斜与随音乐律动。科研模式下若已安装鲸鱼娘立绘则改为显示鲸鱼娘 |
| 程序化动作 | 模型动作文件未包含的 7 种动作——伸爪拍击（`swipe`）、嗅闻（`sniff`）、竖耳警觉（`perk`）、伸懒腰并打哈欠（`stretch`）、舔爪洗脸（`groom`）、甩尾（`swish`）、举双爪抓指针（`grab`）——以关键帧参数轨道实现，叠加于模型当前动作之上，时长 1.8–3.4 秒。每条轨道按 Cubism 2 与 Cubism 3 两种参数命名查找，模型缺少的参数不作处理；关键帧之间以平滑插值过渡，动作首尾各以 0.25 秒淡入淡出。涉及前肢的动作同时显示猫形象的可动前肢部件（`PARTS_01_ARM_*_02`），否则静态前肢部件不随参数运动。上述动作可由对话回复的 `motion` 字段选用，亦参与空闲时的自发小动作：Live2D 角色每 18–45 秒一次，模型自带的空闲动作与上述动作按 3:2 的比例选取（无自带空闲动作的模型仅取上述动作）。图片角色以对应表情图（如 `swipe` 取 `cheer`，`sniff` 取 `think`）与整体补间（位移、旋转、缩放）表演。`grab` 另由指针触发：指针在角色上半身至头顶上方的区域（宽为舞台宽度的 70%，自身高一半处至头顶以上 40% 身高处）内移动累计 0.8 s（指针静止时不累计，移出区域后以两倍速度回减），且距上次不少于 25 s 时，角色立起身体、双爪交替扑抓（右爪抬至 `PARAM_ARM_R_MOVE` 下限 -2.5，左爪至 `PARAM_ARM_L` 下限 -2；头部与视线交由注视控制，故始终看向指针），0.9 s 后原地起跳一次；拖动、跳跃、睡眠、科研模式、淘气行为进行中、聊天框打开或桌面影院放映期间不触发。淘气行为“偷偷溜到鼠标旁”到达后亦以此动作收尾。实测（测试实例，模拟指针于头部附近左右晃动）：约 1 s 后触发，起跳时窗口上移 23 pt |
| 交互 | 拖动移动并记忆位置，角色可贴至屏幕左右边缘与菜单栏下沿；靠近屏幕顶部、上方容纳不下气泡时，气泡改为显示于角色下方（最新一条紧邻角色）；透明像素区域的点击穿透至下层窗口；单击头部触发摸头反应，单击身体打开对话输入框；全局快捷键（默认 ⌥Space，可更换或关闭）呼出或收起输入框；右键菜单。显示层级三选一（右键菜单“显示层级”或“设置 → 通用”）：始终置顶、普通窗口（可被其它窗口遮挡），或仅在桌面（位于桌面图标之上、所有应用窗口之下，气泡亦随之被遮挡，提醒仍以系统通知送达） |
| 对话气泡 | 用户消息与角色回复以气泡形式堆叠于头顶，最多保留 3 条：新气泡位于底部，较早的气泡上移并降低不透明度，各自计时后淡出（科研回答按长度停留 10–30 s，右上角“×”可立即关闭）；指针停留于气泡上时暂停计时，移开后重新计时；窗口伸出屏幕边缘时，气泡与对话输入框自动收回屏幕内 |
| 对话 | 模型以结构化 JSON 返回 `reply`、`motion`、`remind`、`weather_city`、`remember`、`forget`、`open_app`、`add_event`、`agent_task` 与 `claude_task` 字段：`motion` 驱动 17 种语义动作，`remind` 创建一次性提醒，`weather_city` 请求查询其它城市天气后再作答，`remember` 与 `forget` 写入或删除记忆库条目，`open_app` 按名称打开应用（匹配文件名及各语言的本地化名称，仅启动应用），`add_event` 直接将日程写入默认日历（仅受 macOS 日历权限约束） |
| 人设与称呼 | 人设、桌宠名字与对用户的称呼于“设置 → 通用 → 角色”中填写。系统提示词依次包含人设、名字与形象的外形描述（`pet-map.json` 或 `character.json` 的 `look` 字段）；形象的说话习惯（`habit` 字段，如 Tororo 与 Hijiki 的句尾“喵”）仅在使用默认人设时附加，使用自定义人设时，语气、措辞与颜文字的使用均以人设为准，回复与念头的格式说明不另行规定口吻。填写称呼后，发送至模型的系统提示词、上下文、检索出的记忆，记忆整理、念头、观察屏幕与科研模式的提示词，以及执行代理的任务说明中，对用户的指称一律替换为该称呼（“设置 → 主人信息”等界面名称除外），新写入的记忆以该称呼作主语，提醒原文与“📝 记下了”气泡亦作同样替换；未填写称呼时沿用“主人”。应用自身的固定语句（科研模式与联网检索的切换、每日任务、专注计时、语音试听等）采用中性书面表述，不带语气词与颜文字。密码、验证码、密钥与卡号等凭据不写入记忆原文（至多记录存放位置），亦不写入回复与念头（气泡会被朗读，云端语音的音频另存于本地缓存） |
| 音乐律动 | 经 Core Audio 进程对象检测其它应用的音频输出（无需授权，持续 1.5 s 以上方予考虑），并按发声应用（辅助进程按其所属应用）区分来源：音乐播放器（Apple 音乐、网易云音乐、QQ 音乐、Spotify 等）计为音乐；微信、QQ、钉钉、Teams、腾讯会议等聊天与通话应用，IINA、VLC、QuickTime、优酷、哔哩哔哩等视频播放器，以及系统进程（通知、提示音等）一律不计；浏览器及其它应用由声音内容判定。默认经 Core Audio process tap 仅监听上述参与判定的进程（需“系统音频录制”授权，角色自身的猫叫与朗读不在其中），并以系统声音分类器（SoundAnalysis，本机运行）逐窗判别（窗长 1.5 s，重叠一半）：music 置信度不低于 0.4，且不低于 speech 置信度或 singing、rapping 置信度不低于 0.25 时，该窗计为音乐；最近 4 窗中有 3 窗为音乐时判定开始播放，最近 5 窗中有 4 窗不是音乐时判定结束。据此，说话声、以人声为主而叠加背景音乐的视频与单次提示音均不计为音乐。实测：纯语音的 speech 置信度为 0.96–0.99；人声叠加背景音乐时 music 为 0.44–0.78、speech 为 0.89–1.00，均未判为音乐；纯音乐的 music 为 0.74–0.87，约 4 s 后判为播放，结束后约 3 s 停止；监听期间应用进程约占单核 6%–7% 的 CPU。每 0.5 s 一次的进程查询需逐一询问系统音频服务（约 45 个进程时单次约 26 ms，其中本进程 CPU 时间约 0.45 ms，其余为等待），在后台队列执行，不占用主线程，因而不影响窗口移动。节拍由约 150 Hz 以下的低频能量检测，由节拍间隔中位数估计速度，驱动抬头状态下的半拍速左右摆动（是否摆动由念头决定，见“主动行为”）；未获授权、关闭“跟随真实节拍”或系统低于 macOS 14.2 时无法分辨声音内容，仅音乐播放器计为音乐（macOS 14.2 以下仍以任意输出计），并按约 112 BPM 摆动；播放期间角色不进入睡眠 |
| 主动行为 | 念头式搭话（默认开启，参照 Liu 等人 CHI 2025 的 Inner Thoughts 框架）：按“主动闲聊”间隔调用模型一次，依据当前时间与天气、主人的键鼠活动、最近的对话、检索出的记忆与到期的跟进事项产生 1–3 个念头，并为每个念头给出 1–5 分的开口意愿；仅当最高分不低于开口阈值（“健谈程度”：少言 4.5、适中 3.5、健谈 2.5），且所说内容与最近 10 句主动发言的词项余弦相似度低于 0.6 时说出，否则保持沉默。主人每连续一次未回应主动发言，阈值提高 0.5（至多 1.5），主人发言后复位。念头、评分与不开口的原因记入“设置 → 记忆库 → 最近的念头”；说出的话写入当日对话，主人可直接接续。除按间隔触发外，下列情形各触发一次思考，由模型依据情绪、记忆与主人状态决定是否开口及说什么：应用启动；离开 5 分钟以上（进入睡眠）后回到电脑前；摸头（不开口时仅以所选动作回应）；音乐开始播放（模型同时以 `dance` 字段决定是否随节拍摇摆，选择不摇时角色保持静止）及持续 2 分钟以上的音乐停止；“设置 → 提醒”中填写的用餐、上下班、久坐与喝水时刻；天气、DeepSeek 余额与 Claude 额度的提醒，以及淘气行为、桌面图标与桌面影院中发生的事件。思考进行中到达的触发依次排队（至多 3 个）。提示词要求角色关心主人的饮食、作息、用眼与饮水，表述简短、不说教，同一事项提醒一次后不再重复，主人专注时宁可推迟；思考的情境附有主人连续使用电脑的时长（10 分钟以上时）、是否正在听音乐，以及设置中填写的作息（作为参考而非播报时刻）。上述情形均不再使用固定语句：未配置模型、模型调用失败或关闭念头式搭话时，角色不主动发言，到期的提醒与日程除外（见“提醒”）。跟进（默认开启）：记忆整理时由模型为考试、组会、就诊等事项设定跟进时间与问题；到期后，在 8:00–23:00、主人 2 分钟内有操作、距主人上一条消息至少 3 分钟且距上次主动发言至少 10 分钟时触发一次思考，未说出的跟进 45 分钟后重试，第三次仍未说出或逾期 2 天即放弃。科研模式、对话框、每日任务与开机动画进行期间不主动发言。此外，按“自由走动”设置的间隔（偶尔 15–30 分钟、适中 5–10 分钟、活泼 2–4 分钟）沿当前高度跳跃挪位，或在上下方向移动（见“攀爬窗口”），用户打字期间（20 秒内有按键）顺延至停顿后；随机播放舔爪、挠耳等待机动作；用户离开 5 分钟后进入睡眠状态 |
| 猫叫 | 猫形象（`pet-map.json` 中 `"voice": "cat"`）在摸头时发出呼噜声，打招呼、提醒、淘气行为及约 30% 的回复与闲聊时发出叫声；素材为 CC0 真猫录音（见 THIRD_PARTY_NOTICES.md），共 9 段叫声与 1 段呼噜，按情境分为普通、短促、颤音、生气（降调放慢）、委屈五类，每次随机选段并微调播放速率。可在“设置 → 通用”中关闭或调节音量；无声音播放时暂停音频输出，且自身的声音不计入音乐检测 |
| 观察屏幕 | 默认关闭，于“设置 → 提醒 → 观察屏幕”开启，需在“系统设置 → 隐私与安全性 → 录屏与系统录音”中允许 DeskPet（允许后重启桌宠生效）。开启后，主人在电脑前（2 分钟内有键鼠操作）、屏幕未锁定且桌宠未睡眠时，每隔设定间隔（5、10、20、30 或 60 分钟，默认 10 分钟）经 ScreenCaptureKit 截取指针所在显示器的画面（不含桌宠自身的窗口与指针，最长边缩放至 1280 像素，JPEG 质量 0.6），连同前台应用名与窗口标题交给识图服务（可选与对话相同、Claude 或 OpenAI 兼容接口，例如对话用 Claude、识图用 DeepSeek），由其以一句话概括主人此刻在做什么并归为工作、学习、休闲、沟通或其它；需要支持图片输入的模型（Claude 与 DeepSeek 的 `deepseek-flash` 支持，`deepseek-v4-pro` 不支持；截至 2026 年 10 月）。截图不写入磁盘，仅在内存中保留最近 12 条文字描述。同一应用、同一窗口标题 30 分钟内不重复截屏；除主人列出的应用（只记为“在使用某应用”）外，所有应用都截屏并如实描述，描述中不逐字抄写密码、验证码与银行卡号等凭据。桌宠自身在前台时，前台应用取主人上一个使用的应用。20 分钟内的描述以“主人屏幕上”一项附于对话与念头的上下文；记忆整理时附上期间的观察，可据此生成一条概括当段活动的经历。设置页显示权限状态、“现在看一眼”按钮与最近的描述。每次截屏调用一次模型 |
| 语音朗读 | 默认关闭，于“设置 → 通用 → 语音”中开启。开启后角色的气泡被朗读，以下气泡只显示、不朗读：用户本人的消息；执行代理（DeepSeek Harness）与 Claude Code 的交办提示、任务汇报与报错；清理后超过设定字数的长文（“长文不读”，可选 60、120、200、400 字或不限，默认 120 字）。设为不限时，科研回答于句末截取开头约 360 字，并以“其余内容请看气泡”收尾。朗读开启时，角色的气泡（桌面影院中为字幕）在其语音开始时出现，使文字与语音同步：轮到某一气泡后至多等待 3 s，语音未到即先行显示；排队超过 12 s 的气泡、以及待读队列（至多 4 条）溢出时被挤出的气泡直接显示而不再朗读，使语音不致明显滞后于文字；任何情况下气泡至迟在 15 s 内出现。朗读期间角色口型持续开合；用户发送消息或关闭该开关时朗读立即停止，尚未显示的气泡随即显示。朗读前文本经过清理：去除 Markdown 标记、代码块、公式、表格、链接地址、emoji 与颜文字，数字区间中的“–”“~”读作“到”，箭头与波浪号转为停顿，各行末尾补足句读。声音来源二选一。（1）系统语音（离线）：按文本语言（含假名判为日语，含谚文判为韩语，含汉字判为中文，其余判为英语）在已安装的声音中选取，依次按音质（高级、增强、标准）、是否为 Siri 声音、地区是否完全匹配、是否为女声排序；趣味声音不参与选择，Eloquence 声音与旧式 MacinTalk 声音排在最后；也可在设置中指定某一声音。本机仅有标准音质的中文声音时，设置页提示下载高级（Premium）或增强（Enhanced）版本，并可跳转至系统的“阅读与朗读”设置（macOS 15 及更早版本中为“朗读内容”）。（2）云端语音：经 OpenAI 兼容接口 `POST {Base URL}/audio/speech` 分段合成 MP3 音频（按句切分，首段不超过 24 字以缩短开口延迟，其余各段不超过 80 字，过长的句子于逗号处断开），预设为硅基流动 CosyVoice2（`FunAudioLLM/CosyVoice2-0.5B`，默认声音 diana）与 OpenAI `gpt-4o-mini-tts`（请求中附语气描述）；每个气泡入队时即请求其前两段，其后各段在前一段开始播放时请求，使合成与播放并行进行；API key 存于钥匙串（账户 | 记忆库 | 分四层：长期事实（偏好、过敏、重要日期、长期计划等，由模型经 `remember` 字段在对话中写入，并以“📝 记下了”气泡提示）、经历（情景记忆）、印象，以及主人交代的提醒与日历日程（重要度 10，见“提醒”）。记忆整理：一段对话结束 10 分钟后（或新增消息达 24 条时）调用模型一次，将新增消息整理为带日期的经历（重要度 1–10，可附跟进时间与问题）、新的长期事实、对已有条目的改写或删除（参照 mem0 的更新操作；手动添加的条目不可由模型修改）以及至多一条印象；主人消息去除标点后少于 6 字（仅有寒暄）时不调用模型；首次整理回溯 2 天，“设置 → 记忆库 → 立即整理最近的对话”可手动触发。检索（参照 Generative Agents）：每条记忆的得分为保持率 + 重要度/10 + 1.5 × 相关度，相关度为字符一元与二元词项经 BM25 逆文档频率加权后的余弦相似度（以最大值归一化，分母不低于 0.3）与系统离线句向量（NaturalLanguage）相似度离散程度的平均。手动添加的条目、重要度 ≥ 8 的事实、未到期的提醒与至多 3 条印象常驻于系统提示词（上限 1200 字符）；其余条目按得分选取（上限 1800 字符），附于当前消息之前而不写入对话记录，使系统提示词在消息之间保持不变；科研模式与每日任务使用常驻条目与按保持率和重要度选出的条目（上限 2400 字符）。遗忘（参照 MemoryBank 与艾宾浩斯遗忘曲线）：保持率 R = exp(−t/S)，t 为距创建或上次被提起的天数，S = 基数 × 重要度 × (1 + 被提起次数)，基数为事实 30 天、经历 2 天、印象 4 天、提醒 0.25 天；相关度 ≥ 0.6 的条目在对话中计为被提起一次（每 6 小时至多一次），被跟进时亦计一次；自动生成的经历、印象与已给出的提醒在 R < 0.08 且无待跟进事项时删除（重要度 5 且从未被提起的经历约 25 天后删除），事实与手动条目不删除。用户可要求遗忘（`forget` 字段按关键词删除）；条目在“设置 → 记忆库”中按层列出日期、重要度、记忆强度、被提起次数与跟进时间，可手动添加与删除。去重规则（同层内）：规范化后相同、互相包含，或仅存在少量字符插入（较短文本按序保留于较长文本且长度比 ≥ 0.7）时，以新表述替换旧条目；词语替换视为不同事实 |
| Claude 用量 | 若已安装 [Claude Usage Widget](https://github.com/Yu-Xiang-Yang/claude-usage-widget)，只读其写入 `~/Library/Application Support/ClaudeUsageWidget` 的 `quota.json` 与 `history.json`（桌宠本身无需登录）：菜单“Claude 用量”列出 5 小时额度、每周额度及按模型计的每周额度（含重置倒计时）、今日与近 7 天的 token 数与估算成本；“让桌宠报告一下”以气泡播报；闲聊的上下文附带用量，可直接询问剩余额度。每分钟读取一次：5 小时或每周额度达到 70%、90% 时各提醒一次（每个额度窗口内），5 小时额度用至 90% 以上后进入新窗口时提示额度恢复；数据超过 20 分钟未更新时不提醒。提醒内容作为事件触发一次思考，由模型决定是否告知及如何表述；可在“设置 → 提醒”中关闭 |
| Claude API 花费 | 在“设置 → 模型 → Claude API 花费”中填写 Admin API key（`sk-ant-admin…`，由组织账户的管理员在 Claude Console 中创建，个人账户无法创建）后，每 30 分钟（打开右键菜单时若上次查询已超过 1 分钟也会刷新）经 `GET https://api.anthropic.com/v1/organizations/cost_report` 查询组织的花费（按 UTC 日分桶，金额以美分计，约 5 分钟延迟；从当月 1 日或填入余额的日期起，至多回溯 120 天，每页 31 天，至多 4 页）。Claude API 不提供剩余余额的查询接口，因此剩余余额为估算值：主人在 Console 结算页读到余额后填入并点“记下”，记下的时刻、余额与当日此前已有的花费被保存，此后的花费从中扣除（同一组织其它用途的花费也计入）。对话使用 Claude、或观察屏幕使用 Claude 时，右键菜单“Claude API 花费”列出今日（UTC）花费、本月（UTC）花费与估算余额，可让角色报告或打开 Console 结算页；对话上下文附带不超过 1 小时的花费数据。Admin API key 只用于查询花费，存于钥匙串（账户 `anthropic-admin`） |
| DeepSeek 余额 | 在“设置 → 模型”中以 DeepSeek 作为 OpenAI 兼容接口时，每 30 分钟经 `GET https://api.deepseek.com/user/balance` 查询账户余额（打开右键菜单时若上次查询已超过 1 分钟也会刷新）。右键菜单“DeepSeek 余额”显示各币种总余额及其中的赠送与充值部分、是否可正常调用，可让角色报告或打开充值页面；对话上下文附带不超过 1 小时的余额，屏保任务日志显示余额。余额低于 ¥10（美元账户 $1.50）或不足以调用 API 时提醒一次，充值恢复后重新计数，提醒内容作为事件触发一次思考，由模型决定是否告知及如何表述；可在“设置 → 提醒”中关闭 |
| 合盖不休眠 | 右键菜单“合盖不休眠”或对角色说“合上盖子也别休眠”时，经 macOS 管理员授权框（密码或触控 ID）执行 `pmset -a disablesleep 1`，合盖后 Mac 继续运行与联网，仅关闭屏幕；再次切换或说“恢复合盖休眠”时执行 `pmset -a disablesleep 0`。普通的防休眠断言（如 `caffeinate`）只能阻止闲置休眠，无法阻止合盖休眠，故此功能需要管理员权限。该设置为系统级，退出桌宠后保持不变；菜单项以勾选显示当前状态，在电池供电时开启会提示耗电与发热 |
| 天气变化提醒 | 依据“主人信息”中的城市，每 20 分钟获取一次 Open-Meteo 逐小时预报并与当前天气比较：当前无降水而 3 小时内降水概率 ≥ 60%（或降水天气代码且概率 ≥ 40%）时提醒带伞；6 小时内出现雷暴、大雨、大雪或风速 ≥ 45 km/h 时发出预警（两类各 6 小时内至多一次）；17:00 后若明日最高气温较今日变化 ≥ 6 °C 或明日降水概率 ≥ 70%，每日提醒一次。提醒内容作为事件触发一次思考，由模型决定是否告知及如何表述；可在“设置 → 提醒”中关闭或立即检查 |
| 执行代理 | 对话中需要在电脑上动手的任务（文件、命令、在其它应用中操作、在“终端”中打开 ssh 等交互会话后交由用户接手等）由模型以 `agent_task` 字段交给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（需 `npm i -g @deepseek-ai/dsh`，并在“设置 → 模型”中以 DeepSeek 作为 OpenAI 兼容接口），任务直接启动。桌宠以 Agent Client Protocol 启动 `dsh --profile acp` 子进程，默认工作目录为 `~/Documents/DeskPet`，权限模式为 `danger-full-access`：桌宠本身不设限制，执行代理可读写任意文件、运行任意命令，并可经 AppleScript 操作其它应用；其能力边界仅由 macOS 的隐私授权（自动化、辅助功能、日历等，首次使用时由系统询问）与 dsh 自身决定。为缩短耗时，dsh 的推理强度默认为 low（可在右键菜单“执行代理推理强度”中切换为关闭、低、高或最高，下一个任务起生效），并被要求以尽量少的步骤完成任务（合并命令、不写临时脚本、不反复验证）。执行代理被要求优先在图形界面上呈现过程：用户可见的命令在“终端”窗口中执行（远程服务器先 ssh 登录，再于同一窗口输入命令，会话保持打开），汇报所需的输出读取自终端窗口；写入或修改的文件以 `open -R` 在访达中打开所在文件夹并选中；本地与服务器之间的文件传输以 `scp` 在终端窗口中进行并显示进度（未指定位置时下载至 `~/Downloads`，同名文件不覆盖），上传前与下载后于访达中选中相应文件，上传后于同一窗口列出远程目录。dsh 若仍发出审批请求，则于角色下方显示确认卡片，回车允许、Esc 拒绝（卡片出现后 0.6 秒内的按键不计入，120 秒未答复或用户不在电脑前时视为拒绝）。会话日志上传与遥测关闭，单个任务 15 分钟超时。仅用户本人输入的消息可触发 `open_app`、`add_event` 与 `agent_task`，每日任务结果等外部内容不触发，以免网页中植入的指令获得完整权限。完成后角色以气泡汇报结果并记入当日对话；dsh 的诊断输出写入 `~/Library/Application Support/DeskPet/dsh.log` |
| Claude Code | 用户要求交给 Claude，或交代编写代码、修改项目、排查程序问题等开发工作时，模型以 `claude_task` 字段（任务与项目目录）请求；桌宠经 AppleScript 在“终端”中新开窗口，于项目目录启动可交互的 Claude Code 会话（`claude "任务"`，使用本机已登录的 Claude 账号，需 `npm install -g @anthropic-ai/claude-code` 并登录），任务作为首条消息发出，用户可观察全过程并继续对话。未指明项目时使用“设置 → 通用 → Claude Code（开发任务）”中的默认项目目录。文件修改与命令执行由 Claude Code 自身的权限确认把关，桌宠不另设限制；首次使用时 macOS 请求“自动化”授权（DeskPet 控制“终端”）。简单命令、查看信息与文件传输仍由执行代理完成 |
| 日历日程提醒 | 默认关闭，于“设置 → 提醒 → 日历”开启，首次开启时由系统请求日历读取权限（`EventKit` 完全访问，仅读取，不修改日历）。读取“日历”App 中的全部日程，包括已同步的 iCloud、Google 与 Exchange 账户；已取消的日程及本人已拒绝的邀请不予提醒。每分钟（日历数据库变更时立即重新读取）将今明两天尚未开始的日程（开始不足 5 分钟者仍计入）与当日未结束的全天日程同步至记忆库的“提醒”层：条目文本含日期、星期、起止时间、标题与地点，到期时间为开始前 N 分钟（默认 10 分钟，可调为 1–120 分钟），全天日程为当日 08:30；改期或改名时更新尚未给出的条目，从日历中删除的日程同步移除，已给出的条目不再变动。到期后的提醒方式见“提醒”；不再于每日早晨播报当日日程，当日安排由常驻于系统提示词的提醒条目供角色知晓。屏保任务日志显示下一项日程。另可开启“聊天时让角色知道今明两天的日程”（默认关闭）：开启后，今日剩余与明日日程的标题、时间与地点附于对话上下文，并随消息发送至所选的模型服务 |
| 主人信息 | “设置 → 主人信息”中的所在城市（闲聊上下文附带当地天气，缓存 30 分钟）与自由文本背景，附加于闲聊、科研与每日任务的系统提示词 |
| 检索工具 | Claude 另可使用服务端 `web_search`；两种服务均可调用客户端工具 `search_arxiv`、`search_semantic_scholar`、`search_news`、`get_stock_quotes`、`get_weather` 与 `fetch_webpage`（详见第 6 节） |

## 2. 系统要求

- macOS 14 或更高版本（音乐节拍跟随需要 macOS 14.2 或更高版本）；
- Xcode Command Line Tools（提供 `swiftc`，无需完整 Xcode）；
- 构建时需要网络连接，用于下载固定版本的前端库。

## 3. 构建与安装

```bash
./build.sh
```

```bash
./build.sh install
```

`./build.sh` 生成 `build/DeskPet.app`；`./build.sh install` 另将其复制至 `/Applications`（无写入权限时为 `~/Applications`）。首次构建时，`scripts/fetch-vendor.sh` 下载以下前端库至 `Resources/web/vendor/` 并逐一校验 SHA-256：pixi.js 6.5.10、pixi-live2d-display 0.4.0（Cubism 4 构建）、marked 12.0.2、DOMPurify 3.1.6、KaTeX 0.16.11（含 woff2 字体）、highlight.js 11.10.0。运行时不访问任何 CDN。

可选的本机千问语音（仅 Apple 芯片）：`scripts/local-voice/install.sh <参考录音.wav> "<录音中的原话>" [声音名称]` 准备运行环境、模型与参考声音，`scripts/local-voice/uninstall.sh` 将其移除，详见“语音朗读”。

未配置签名证书时，应用以 ad-hoc 方式签名，每次重新构建后签名改变，macOS 将再次请求钥匙串与“系统音频录制”授权。在“钥匙串访问 → 证书助理 → 创建证书…”中创建名称为 `DeskPet Code Signing`、身份类型为“自签名根证书”、证书类型为“代码签名”的证书后，`build.sh` 即以其签名，授权在重新构建后仍然有效。

## 4. 模型服务配置

首次启动且钥匙串中不存在 API key 时，应用自动打开“设置 → 模型”页。

| 服务 | 配置项 | 说明 |
| --- | --- | --- |
| Claude (Anthropic) | API key、模型名（默认 `claude-opus-5-5`）、拒答回退开关 | 通过 Messages API 流式调用；宠物对话使用 `effort: low` 与结构化输出，科研对话使用 `effort: high`；开启回退时，对支持的模型附带 `fallbacks: "default"`（beta `server-side-fallback-2026-07-01`） |

## 6. 科研模式与检索工具

- 进入方式：角色右键菜单或状态栏菜单中的“科研模式”开关。开启后首个问题新建一个科研对话，此后的问题追加至该对话；“开始新的科研话题”另起对话；“联网检索（较慢）”开关控制是否提供检索工具。
- 回答篇幅：默认先给出结论，正文控制在 300–600 字；用户明确要求时再展开。
- 工具循环：单轮最多 3 次模型调用（至多 2 轮工具调用，第 3 次调用禁止工具）；同一轮的全部工具调用并行执行，结果合并为一条消息回传；`pause_turn` 时原样回传后继续。
- 检索工具：

| 工具 | 数据来源 | 说明 |
| --- | --- | --- |
| `search_arxiv` | arXiv API | 预印本检索 |
| `search_semantic_scholar` | Semantic Scholar API | 已发表论文检索 |
| `search_news` | Bing News RSS，失败时 Google News RSS | 新闻按时间倒序 |
| `get_stock_quotes` | Yahoo Finance | 股票、指数与 ETF 行情，6 位 A 股代码自动换算为 `.SS`/`.SZ` |
| `get_weather` | Open-Meteo | 当前天气与 1–7 天预报，支持中文地名 |
| `fetch_webpage` | 任意公网网页 | 仅允许公网 http/https 地址，提取正文至约 6000 字符 |

- 稳定性：单次请求超时 12 s；HTTP 429/503 仅重试一次，同一主机此后 60 s 内直接返回错误，以便模型改用其它来源；相同检索 10 分钟内复用缓存。
- 历史回放：Claude 的助手消息以原始内容块保存，并在后续请求中原样回传，使历史保持只追加；切换服务后，历史以纯文本形式回放。

| API key（含 Claude Admin API key） | 钥匙串（service `local.deskpet`） |

应用仅向以下地址发起网络请求：所选模型服务的 API 地址、`export.arxiv.org`、`api.semanticscholar.org`、`www.bing.com`、`news.google.com`、`query1.finance.yahoo.com`、`api.open-meteo.com` 与 `geocoding-api.open-meteo.com`，以及模型通过 `fetch_webpage` 指定的公网网页；本机千问语音仅监听 127.0.0.1，模型以离线模式加载，不访问网络；开启云端语音时，另向所设语音服务的地址（默认 `api.siliconflow.cn`）发送待朗读的气泡文字；开启观察屏幕时，屏幕截图与前台应用名、窗口标题发送至所选模型服务。系统音频仅在本机实时分析节拍与声音类别，不录制、不保存、不上传。环境变量 `DESKPET_DIR` 可覆盖数据目录并启用测试钥匙串项，供测试使用。
